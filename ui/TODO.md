# PaySift UI outcomes

- [x] **Bundled static data and adapters.** `DataSource` supports health, list/get run, kill matrix, break, repair and static scenario/spec/hash/status/report. Live API uses documented endpoints, configurable API base, friendly JSON errors, abort support and long repair timeout. Static bundle copies supplied files and excludes samples from normal runs.
- [ ] **Global shell and accessible navigation.** Keep the dark forensic-ledger identity, cream receipts, red/amber/green signals, monospace labels and self-hosted fonts. Remove FPS/GPU/CPU/LAT readout and floating circular close control. Give the sticky header a translucent background, blur and border; distinguish animated active-nav indicator from a separate focus-visible ring. Show neutral `STATIC SNAPSHOT` or green, pulsing `LIVE API` with tooltip. Make `⌘K` open a working cmdk palette that navigates to pages, R0–R10, candidates and runs. Use consistent PaySift branding. Add a mobile nav sheet. Do not ship dev overlays or evidence fixtures in production.
- [ ] **Motion, responsiveness and accessibility.** Use transform/opacity-only GPU-safe motion; respect `prefers-reduced-motion`. Maintain WCAG AA contrast, keyboard operation, accessible labels, focus-visible states, and icon-plus-text statuses. Prevent page-level horizontal overflow and inspect widths 390, 768, 1280, 1440 and 1920px.
- [ ] **Landing dashboard.** Use the headline “AI writes payment code that passes demos. PaySift finds the rupee it invents.” Keep data-driven failure detail and `HAND-WRITTEN MUTANT` provenance in the hero card, never in a model-claim headline. Balance hero columns. Replace blocker prose with a source-data-driven StatusBoard covering Docker, models, sandbox gate, pilot and repair with `ok`, `blocked` or `not run` states. Derive stat tiles and mutant split from kill-matrix rows; remove/relabel meaningless seed bounds; label reproduction and largest minimal stream clearly; animate counts, show hover detail and copy-on-click SHA. Meet AA contrast on the featured cream failure card and use a proper sandbox status pill. Hide the evidence stat when grounding data is unavailable; if data exists, show `N of 11 rules backed by cited sources`.
- [ ] **Findings and shrink playback.** Derive mutant provenance from matrix kind/candidate identity so `m*` shows `HAND-WRITTEN MUTANT`, `x*` shows `EXTRA-MUTANT`; never describe either as model output. Keep `REFERENCE`, `MODEL`, `ILLUSTRATIVE`, and `unreviewed · agent-proposed` honesty labels. Format dates as `20 Nov 2026` without wrapping. Colour-code financial/interface failure counts. Make rows keyboard/click operable and expand inline into the shrink player. Shared ShrinkPlayer supports play/pause/step/scrub/speed and animates only supplied data; when only original and minimal traces exist, fade out non-minimal events and label them `removed by shrinker`, without inventing intermediate steps.
- [ ] **Kill matrix heatmap.** Derive counts and splits from rows, including `13/13 killed (9 hand-written + 4 extra) · reference clean` only when supported by data. Group Reference / Hand-written / Extra rows. Use sticky header and first column, scroll shadows, fail-count cell colors, outlined intended-rule cells, tooltips with rules hit and notes, `—` legend for not applicable, candidate id plus description, and first-view row motion. Dynamically derive invariant key names.
- [ ] **Break it scenario lab.** At desktop widths use a 320–360px scenario rail and a min-width-zero result panel; stack expected/observed receipts below 1100px. Prevent horizontal page overflow. Render ledger/payments as tables with entry, kind, ₹ amount and event id; retain raw JSON in a collapsible copyable block. Highlight extra/missing rows. Open supplied step verdicts by default as an EventTimeline. Disable `Run live` in static mode and explain why in a visible tooltip.
- [ ] **Repair loop.** Disable `Ask the model to fix it` in static mode with an explicit reason. Replace the void with a designed empty state and flow diagram: failure → prompt (rule + cited sources) → fix → full suite re-run → verdict. Render before/after DiffViewer, invariant before/after table, and “Sources given to the model” only when real result data supplies them. Clearly flag a repair that breaks another invariant.
- [ ] **Pilot state.** When `n=0`, show exactly `No pilot run yet` and a status-driven Docker → keys → generate → pilot stepper. Prepare real-data results with candidate grid, per-invariant pass/fail, minimal trace length, alphabetical default order and `NO RANKING` banner. Mark Condition B `ILLUSTRATIVE`. Never show the nonsensical `0 of 0 compliant handlers broke…` claim.
- [ ] **Specification and rules.** Parse rule ids/titles; render headings like `R0 · Totality & Interface`, not raw markdown. Use auto-fill `minmax(320px,1fr)` equal-height rule cards expandable to full text. Label usage `Violated in N runs` and link to filtered Findings. Render full supplied contract through ReactMarkdown + remark-gfm with real headings, tables, lightweight Python/SQL/JSON code styling, copy buttons, sticky TOC/scrollspy, `#r3` anchors, and ₹ values in examples.
- [ ] **Method pipeline.** Replace misaligned timeline cards with an animated SVG/pipeline whose line draws on scroll. Each stage has an icon, plain-language description without implementation-status jargon, and status chip derived from supplied data.
- [x] **Evidence grounding adapter.** Centralize all mapping in `src/data/grounding.ts` using the provisional spec_sha/generated_at/rules schema and label enum `SUPPORTED|PARTIAL|NOT_FOUND|CONFLICT|NOT_JUDGED`. Tolerate a missing `runs/grounding.json`; show exactly `Evidence not retrieved yet` when absent. EvidencePanel may render only adapter-sourced source records, with convention tag when unsupported, LIVE/CACHED and retrieval date, domain/title/snippet/outbound link, and the wording `supporting sources, retrieved <date>`—never `verified`. `Why is this a bug?` is live-mode only; its endpoint is one constant and now handles live search with cached fallback. Optional `/gaps` lists PARTIAL/NOT_FOUND/CONFLICT as questions for review. Development-only `?fixture=evidence` has an obvious `SAMPLE DATA` ribbon and is excluded from production. Do not claim You.com retrieval without an authorized connector/result.
- [x] **Forensic shared UI and data honesty baseline.** Dark ink/warm paper palette, provenance badges, DRAFT-FROZEN/stale states, dynamic invariant scores, receipt/stamp motifs, reduced-motion styles, and honest limitations exist in the inherited implementation.
- [x] **Runs, detail and failure deep-dive baseline.** Existing routes include filters, latest-per-candidate, tolerant details, invariant summaries, traces, event alignment, ledger comparison, raw source and failure actions.
- [x] **Existing routes, scripts and deliverables baseline.** Keep all existing routes including `/dev/contract` and `/dev/sample`; preserve `sync-data`, `check:contract`, `check:api`, `verify`, and `dev`. Keep `public/manus-routes.json` synchronized.
- [ ] **Release handoff.** `npm run verify` and `npm run check:contract` pass; static build works without backend/Wi-Fi; no console errors, production dev overlays, or page-level overflow at the five specified widths. Sync final source copy, update and validate the project ZIP, and include `CHANGES.md` listing changes, touched files, decisions and anything not done. Keep the managed preview running and do not publish.
